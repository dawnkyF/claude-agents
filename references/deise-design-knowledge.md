# Deise 设计知识库（做任何 UI / 视觉任务前必读）

> 这份文件是我的长期记忆，不是一次性笔记。
> 来源：2026-11 对本项目三套主题被否后的复盘 + 对成熟产品的实机与文档研究。
> 规则：**具体数字优先于形容词**。写「行高 88px、封面 48×64」而不是「疏朗、精致」。
> 每次接 UI 任务：先读本文件 → 再出《设计简报》→ 再定方向。不要凭印象起稿。

## 零、一句话总纲

**界面本身要无色、无声、无装饰；把所有的颜色预算和视觉重量留给内容（封面、文字）。**
判断一个决定对不对，只问一句：**它是在衬托内容，还是在跟内容抢注意力？**

## 一、中文界面的字号阶梯（硬数字）

| 角色 | 字号 | 说明 |
|---|---|---|
| 微标签 | 12px | 仅用于时间戳、计数、单位。字距 0，不加 letter-spacing |
| 元信息 | 13px | 作者、分类、状态、徽标、筛选选项。**这是中文高密度列表的下限** |
| 界面正文 | 14px | 按钮、输入框、提示 |
| 引文 / 长引 | 15px | 划线原文、引用块。行高 28 |
| 列表主标题 | 17px | 书名（宋体）。**低于 15px 的宋体在中文里会糊成一片** |
| 区块标题 | 20px | 分组标题、空态标题 |
| 详情标题 | 26 / 32px | 窄屏 26，Web 32 |
| 大字 | 40px | 统计页数字、读后感页标题 |

**铁律**
- 中文 12px 是可读性地板，14px 是标准正文。**不要为了塞信息把 6 个字段全压到 10–11px** —— 这是"表格导出感"的第一来源。
- 宋体只用于 ≥15px。宋体细横在低分屏会消失。
- 宋体字重最多到 600；17px 以下用 700 会堵死字怀，糊成黑块。
- 长文（读后感、引文）行高 1.85–1.9；界面行高 1.5。
- 数字一律等宽（`font-variant-numeric: tabular-nums`）。百分比列、日期列、字数要**纵向对齐成一条竖线**，否则扫读时数字会左右跳。
- 字距：标题 −0.012 ~ −0.015em；微标签 +0.06em；正文 0。永远不要低于 −0.04em。

## 二、颜色：按角色分配，不按字段分配

**四个层次，不要更多**
1. 纸（页面底 / 侧栏底）：比内容区**略深或略浅一档**，靠明度差分区，不靠边框
2. 面（内容区 / 行 / 面板 / 输入框）
3. 线（分隔 1px / 控件描边 / 悬停描边）—— 三个明度等级
4. 墨（主文 / 次文 / 弱文）—— 三个等级，弱文必须 ≥4.5:1

**唯一彩色 = 一个强调色。** 用法：
- 先问「这个产品里，什么才配得上唯一的颜色？」答案通常是**用户的痕迹**或**需要用户处理的事**。
- 然后列出它**允许出现的全部位置**（写成一个清单，通常 5–7 处），其余一律禁止。
- 判定口诀：**红 = 你的痕迹，或需要你处理的事。凡不是这两者的，都不是红的。**
- 强调色最常见被滥用成：状态色、分类色、链接色、选中底色、主按钮、图表色。**全部禁止。**

**彩色预算归内容**：如果内容本身是彩色的（书封面、封面海报、商品图），那界面必须近乎无色。反过来才成立。这一条能立刻把界面从"模板感"里救出来。

**反差**：正文 ≥4.5:1。**弱化文本不要靠降低对比度到不可读**，靠字号和字重。

## 三、列表界面的解剖学（最重要的一节）

### 3.1 不要把 N 个字段做成 N 个等宽列

**这是「电子表格导出感」的定义。** 成熟产品（Linear / Notion / Letterboxd / Readwise / Zotero）的做法一致：

- **只有一个弹性列**（通常是最长的那个：标题），其余列全部定宽
- **列宽悬殊**：主列 300–460px，其余 40–120px
- **不加表头行**（操作型列表）；表头只在富表格里出现
- 字段按**语义聚成 2–4 簇**，簇之间才留间距，簇内紧凑

本项目实证（书架行 → 三簇）：
```
[ 身份 ]        →  [ 状态 · 进度 ]  →  [ 我的产出 ]    →  [ 时间 ]
封面 / 书名 / 作者·分类   状态 / 进度      我的评分 / 读后感     最后阅读
```
> PRD 要求的 9 个字段全部保留，但形态从"9 列平铺"变成"3 簇 + 1 末列"。

### 3.2 行网格模板

```css
display: grid;
grid-template-columns: 48px minmax(320px, 1fr) 72px 88px 120px 96px 76px;
column-gap: 20px;
align-items: center;
min-height: 88px;
```
- 定宽列之和 + gap 之和 = 容器宽（算准，不要"差一点"）
- **主列左侧留下的空白是正常的**（宽首列的自然形态），不要为了填满而拉伸短元素
- 短元素**左对齐在固定列里**，让它们跨行形成一条竖线

### 3.3 每个格子的形态要能"不靠颜色"区分

状态、进度、是否写过 —— 全部用**形状/图标/文字**区分，颜色只做锦上添花。
- 三态用三种图标：空心圆 / 铅笔 / 实心圆
- 状态用 bookmark / book-open / check
- 进度用「数字 + 轨道」：轨道起点固定，数字定宽右对齐

### 3.4 行高与密度

| 密度 | 行高 | 封面 | 一屏(1440×900) | 适用 |
|---|---|---|---|---|
| 紧凑 | 44–56px | 24–32×32–44 | 14–18 | 定位为主、几百条以上 |
| 舒展 | 88px | 48×64 | 7–9 | 单个用户、偶尔翻、要"像印出来" |

**行高决定一切其他尺寸**：封面 = 行高 − 24（上下各 12），行高取 8 的倍数。

## 四、缩略图与「缺失」——最容易被做错的一处

### 4.1 尺寸

列表缩略图落在 **44–56px 宽**这个带宽（Goodreads / Apple Books / Letterboxd 都在这）。小于 44 就退化成色块（人靠封面的**颜色和版式**认物，不是靠读上面的字）；大于 56 就要把行高推到 100+。

### 4.2 缺失的正确答案：**留空，真的空**

| 做法 | 判定 |
|---|---|
| 保持槽位尺寸的**透明矩形**：无底色、无边框、无图标、无文字 | ✅ 唯一正确 |
| 灰色实心方块 / 破图图标 | ❌ Kindle "No image available"，把缺失放大成错误 |
| 虚线框 / 斜纹 | ❌ "这里该放东西"的占位语义，更显眼 |
| **用首字 / 色块伪造一个封面** | ❌ 最严重 —— 伪造内容本体 |
| AI 生成 / 渐变 / 拼贴封面 | ❌ 伪造内容本体 |

**原理**：在列表里缩略图是**识别辅助**，不是内容本体。灰块提供不了识别还制造噪音；白框是"这里缺东西"的通用错误符号。
**正确做法 = 几何保持一致（不塌陷、不错位）+ 缺席保持沉默（不加任何标记）+ 可读性交给旁边的标题。**
加载中才显示 `--surface-2` 实心块，且**不做 shimmer**。


### 4.4 实测教训：封面源不是统一比例，还会用哨兵图冒充缺失

- **比例不统一**：同一个源的封面在 0.69–0.75 之间（约 2:3 到 3:4）。→ 固定槽位 + `object-fit: contain`，**永远不要 `cover`**。
- **哨兵图**：接口可能用 1×1 或 72×72 的图表示"没有封面"。→ 「缺封面」的判定必须是 `URL 空 或 固有宽度 < 30px 或 宽高比≈1`，不能只看 URL 是否为空。否则列表里会出现被拉伸成色块的 1×1 图。
- 这是"内容由上游决定"的典型后果：**凡是外部图片源，都要假设它的尺寸、比例、缺失表示方式都不可靠**，在入库前校验一次，而不是在渲染时补救。

### 4.3 不要做的事

- 不二次裁切、不加滤镜、不加暗角、不在封面上叠字
- 用 `object-fit: contain` 而不是 `cover`，除非确认所有源图同比例

## 五、控件与筛选

- **状态型筛选优先用「纯文字 + 字重变化」，不要圆角 chip**。chip 是 SaaS 模板最强的气味来源之一。
  - 选中：`--ink-1` + 600；未选中：`--ink-3` + 400；分隔用 ` · `；计数用 mono 12px
- 排序 / 分组：文字 + `chevron-down` 12px，不加边框
- 多选维度（如分类）才做成 `标签 ▾` 弹出复选面板
- 搜索框：无底色 + 1px 描边 + 高 36，右侧 `⌘K` mono 提示
- **不要图标-only 的工具栏**；**不要浮动在内容上的排序下拉**

## 六、交互状态（必须全部设计）

| 状态 | 要点 |
|---|---|
| 悬停 | 只改底色一档（120ms ease-out）。**不位移、不加阴影、不加边框**。行内操作按钮用 opacity/transform 显隐，**禁止插入 DOM 造成跳动** |
| 焦点 | 2px 描边 + `outline-offset: -2px`；对比 ≥3:1（WCAG 2.2 §2.4.13） |
| 选中 | 左边缘 2px 竖条，不叠加焦点环 |
| 评分预览 | 指针位置及左侧变强调色，右侧保持空心 |
| 同步中 | 不用旋转菊花；用一条 2px 进度线匀速横移 |
| 折叠组 | height + opacity，组内行 12ms stagger |

## 七、空态 / 加载态 / 错误态

- **空态**：标题（20px 宋体 600）+ 两行说明（14px）+ 一个主按钮。**不画插画、不画假内容、不画图标墙。**
- **加载态**：骨架行（与真实行同高同格），不做 shimmer；顶部一条 2px 进度线。
- **错误态**：说清**失败在哪一步** + 重试按钮。整页不铺红底，错误色只出现在一条竖条和一个图标上。

## 八、让界面显廉价的 12 件事（出现任意一条就重做）

1. 把 N 个字段做成 N 个等宽列 + 表头行
2. 6 个字段里 5 个是 10–11px（字号阶梯在底部塌陷）
3. 颜色按字段分配（分类一种色、状态一种色、评分一种色），一行 5 种颜色互抢
4. 圆角 chip 做的筛选条
5. 缩略图小于 44px，退化成一个色块
6. 缺图时画灰块 / 白框 / 首字色块
7. 每块内容用同一个间距值（全部 24px），读者无处落脚
8. 卡片 + 居中 + 阴影三件套
9. 图标-only 工具栏，无文字标签
10. hover 才出现的关键操作（触屏上没有 hover）
11. 默认框架的表格 / 默认的表单控件，不改外观
12. 用"换明度"来假装"换方向"（米色纸 / 燕麦纸 / 深棕纸是同一个世界）

**另一类**：中英混排里塞装饰性英文小字（"POWERFUL FEATURES"），一律不要。

## 九、场景判断先于风格（沿用原有流程）

| 场景 | 好布局的定义 |
|---|---|
| 说服 Persuade | 敢站定一个视觉立场；可破格、可不对称 |
| 操作 Operate | 可预测、密度稳定、位置不搬家；**破格是缺陷** |
| 阅读 Read | 线性路径、正文 65–75ch、导航在该在的位置 |

**操作页与阅读页不要破格。** 唯一的"破格"留给内容本身（例如：界面用无衬线、书名用衬线 —— 让"内容用衬线、界面用无衬线"成为唯一的反差）。

## 十、本项目裁决记录（不要重犯）

**2026-11，三套主题（台账 / 书房杂志 / 夜读）被用户判定「太丑」。** 复盘出的六个结构性错误：

1. 9 个字段做成 9 个平级列 + 表头 → 电子表格导出感
2. 封面被当装饰芯片（30×40）→ 认不出书
3. 字号阶梯在底部塌陷（9 个字段里 6 个 10–11px）
4. 颜色按字段分配而非按角色分配
5. 三套主题是同一个世界的三种明度（换明度 ≠ 换世界）
6. 没有一个属于内容自己的"物件"—— 最该有的签名物（用户在书上留下的痕迹）被降级成一个 10px 标签

**修正方向：「朱批（Rubrication）」** —— 像一本被自己用红笔批注过的书的目录页：白纸、黑墨、一支红笔。
- 纸 `#F7F8F9` / `#FFFFFF`；墨 `#14171A` / `#4C545C` / `#676F77`；线 `#ECEEF1` / `#DDE1E5` / `#C6CBD1`；朱 `#C4362B`
- 侧栏 232px + 容器 1080px 居中；行高 88px；封面 48×64；一屏约 8 本
- 朱红只出现在 6 处：已点亮的星 / 草稿中 / 已从微信读书移除 / 焦点环 / 同步失败 / 品牌竖条
- 完整规范见项目内 `docs/设计主题方案-v2.md`

**教训**：先研究再动笔。v1 是"照着文字 token 直接画"，没有看过任何真实产品怎么处理一行书。**没有参照物的 token 规范，出来的一定是模板。**

## 十二、动效：真实的 token 值（不要凭感觉给数字）

### 12.1 各家系统实际发布的时长

| 系统 | 快 | 中 | 慢 |
|---|---|---|---|
| Material 3 | 50 / 100 / 150 / 200ms | 250 / 300 / 350 / 400ms | 450–600ms |
| IBM Carbon | 70ms（微交互）/ 110ms（淡入） | 150 / 240ms | 400 / 700ms |
| Atlassian | 50ms（列表悬停）/ 100 / 150ms | 200 / 250ms | 400 / 600ms |
| Shopify Polaris | 0–500ms，50ms 一档，常用 100/200/300 | | |

**缓动**：Material `(0.2,0,0,1)`；Carbon productive `(0.2,0,0.38,0.9)`；Polaris out `(0.19,0.91,0.38,1)`；**Linear 用的是 out-quint `(0.23,1,0.32,1)`（teardown，非官方）**。

### 12.2 交互类别 → 时长

| 类别 | 区间 | 例 |
|---|---|---|
| 键盘选择 / 直接操作 | 0–50ms | 列表选中（Raycast 干脆不做动画） |
| 悬停、按下、颜色反馈 | 70–150ms | Carbon 70/110；Linear 实测 ~100 |
| 小进入（tooltip、浮层、行内动作） | 150–250ms | Atlassian 150、Carbon 240 |
| 小退出 | 100–180ms | 比进入短 50–100ms |
| 展开 / 布局变化 | 200–300ms | Material 300、Carbon 240 |
| 页面切换 | 300–500ms | Material 500、Atlassian 400 |
| 不确定进度循环 | 1800–2000ms | Material Components Android 1800 |
| 列表级差 | 每项 20–50ms，总量封顶 200–300ms | Material 20–40 |

### 12.3 三条容易被违反的规则

1. **退出比进入快 70–80%。** Material Emphasized：进 400 / 出 200（50%）；Atlassian：进 150 / 出 100（67%）。
   **唯一的例外是悬停底色**：进 90ms、出 120ms 更慢——指针扫过多行时，拖尾淡出能防止闪烁。这个例外要刻意为之。
2. **级差低于 20ms 等于没有。** 12ms 会被读成一整块同时出现；40ms × 20 行 = 800ms，会被读成卡住。**20–24ms、封顶 8 行 / 200ms。收起时不要级差**（要就 10ms 反向）。
3. **不要动画焦点环。** 焦点是 0ms 状态。淡入、缩放、延迟都会让键盘导航发飘，并遮住用户"我在哪"的判断。

### 12.4 建议 token（本项目在用）

```
--dur-hover-in 90ms / --dur-hover-out 120ms
--dur-act-in 140ms (悬停时延迟 90ms 触发) / --dur-act-out 90ms
--dur-expand 240ms in-out / --dur-collapse 160ms in
--dur-sync 1800ms linear
--ease-out cubic-bezier(.2,0,0,1) / --ease-in cubic-bezier(.3,0,1,1)
```

### 12.5 感知阈值

**100ms** 感觉瞬时（评分、悬停、选中、本地筛选）；**1s** 思路不断但能察觉；**10s** 注意力上限，必须给进度和取消。
→ **100ms 内完成的事不要显示任何 loading。300ms 内不要显示菊花。** 显示过的指示器最少留 400ms，否则会闪成故障。

## 十三、交互：让成熟产品"对"的那些细节

### 13.1 悬停揭示动作（reveal-on-hover）的正确做法

这是最容易做坏的一处，五条缺一不可：

1. **预留固定槽位。** 槽宽按**最长的动作文案**（"写读后感"）算，不按当前文案算；否则日期列和标题在每次悬停时抖动。
2. **两层叠在同一个 grid 格子里交叉淡入**：`display:grid; > * { grid-area:1/1 }`。格子按最高子元素定高，**行高永不变化**。只动 `opacity`。
3. **`:focus-within` 必须能reveal**。`opacity:0` 不会把元素移出 Tab 序列——键盘用户会 Tab 到一个看不见的东西上。这是该模式**最常见的 bug**。
4. **hover-intent 延迟 90–100ms**，只加在动作簇上，底色不加。否则扫过 20 行会闪 20 个按钮。
5. **触屏必须常驻**：`@media (hover:none),(pointer:coarse)` 直接显示，不要指望 tap 出 hover（通常要两次点击，像坏了）。

### 13.2 键盘模型

- **记录型列表用 APG 的 grid（layout grid），不要用 listbox。** listbox 里 `option` 不允许有交互子元素，行内的星级和动作会被拍平、读屏读不到。table 模式则规定"单元格不可聚焦"。
- **一个复合 Tab 停点 + roving tabindex**：只有当前行 `tabindex=0`，其余 `-1`。
- 键位：`↑↓` 移动、`Home/End`、`PageUp/PageDown`、`Enter` 打开、`→` 进入行内控件、`←` 退回行。
- **焦点与选中必须分离。** 方向键只移动焦点环，`Enter` 才切换"当前打开的行"。焦点跟随选中只适用于详情即时可见的选择器。
- **不要给行加 `role="button"` 再在里面套按钮** —— 嵌套交互，读屏输出不可预测。
- 动作按钮的无障碍名要带对象：`写《书名》的读后感`。

### 13.3 焦点环

```css
.row-cell:focus-visible{outline:2px solid var(--vermilion);outline-offset:-2px;border-radius:2px}
```
- **2px 周长 + 同一像素处对比变化 ≥3:1**（WCAG 2.4.13）；1px 单边下划线不达标。
- `outline-offset:-2px` 让环落在盒内，不会被 `overflow:hidden` 裁掉。
- `outline` 从 Chrome 94 / Firefox 88 / Safari 16.4 起跟随 `border-radius`，不再需要 box-shadow 兜底。
- **sticky 头部遮住焦点** 是最典型的失败（F110）：给滚动容器加 `scroll-padding-top`。
- 深色/有色底上用**双环**（内浅外深，两色互相对比 ≥9:1）。
- `:focus-visible` ≠ `:focus`：前者只在 UA 判断"该显示"时命中（Tab 一定、鼠标点按钮通常不、输入框总是）。

### 13.4 乐观更新（评分这类低风险可逆操作）

- 三个值分开存：`committed / hoverPreview / pending`，渲染 `hoverPreview ?? pending ?? committed`。
- 点击立即落定，**不用菊花**。填充本身就是确认。
- 保存 <300ms 什么都别显示；超了再显示 2px 朱红下划线或「保存中…」。
- 失败**在行内**回滚（200ms）+ 提示「评分未保存 · 重试」，**不要用全局 toast**。
- 悬停预览**不改变 `aria-valuenow`**，只改视觉。
- 防连点：每个对象带单调版本号，丢弃过期响应。

### 13.5 分组折叠

- 用 `grid-template-rows: 0fr → 1fr`，不要 `height:auto` 补间。
- 展开 240ms / 收起 160ms；箭头 180ms 同起，不要等展开完再转。
- 收起前若焦点在组内，先把焦点移到组头。
- `aria-expanded` + `aria-controls`。

### 13.6 两栏独立滚动（阅读类详情页最容易做坏）

```css
.col-scroll{overflow-y:auto;min-height:0;overscroll-behavior:contain;
 scrollbar-gutter:stable;scroll-padding-top:calc(var(--h) + 8px)}
```
- **`min-height:0` 是必须的**，否则 flex 子元素拒绝滚动。
- **`scrollbar-gutter:stable` 两栏都加**，否则一栏出滚动条时文字左边缘会跳，两栏对不齐。
- 不要用 `overflow:scroll` 假装"两栏都有滚动条"。
- 不要做滚动劫持/平滑滚动；只有"跳到某条划线"这种程序化跳转可以用 smooth，且要在 `prefers-reduced-motion:no-preference` 下。

### 13.7 自动保存

防抖 **本地 800ms / 服务端 1.5–2s**。状态只有文字，不用菊花。
四态：`idle / 未保存 / 正在保存… / 已保存`。"已保存"停留 2s 后变成「已保存 · 刚刚」或时间戳。
`aria-live="polite"`，**不要每敲一个字就播报**。失焦、路由切换、`pagehide` 时强制冲刷。

### 13.8 删除与撤销

乐观移除 + 服务端软删；行 120ms 透明度 + 180ms 高度收起；提示条 150ms 进入、**8 秒**窗口；**鼠标悬停与键盘聚焦时暂停计时**；**带焦点的提示条绝不自动消失**（焦点会掉到 body）；删除后焦点移到下一行。


### 13.9 可点性与分组：两个最常翻车的地方

**「分不清哪里能点」几乎总是三个原因叠加**：热区只贴着字、悬停没有任何变化、可点与不可点的东西长得一样。

- **热区 ≥ 28×28**，按钮左右内距至少 8–10px。鼠标不需要瞄准字形。
- **可点元素悬停必须有一次可见变化**（底色一档）。**不可点的标记绝不加悬停变化**。两者都不给，用户才知道边界。
- **悬停与选中必须用不同通道**：悬停 = 临时底色；选中 = 持久下划线 / 加粗 / 左侧竖条。否则悬停会被误读成"已经选了"。
- 需要扩热区又不想占布局时，用伪元素外扩：`::before{position:absolute;inset:-6px -10px}`，不要用 padding 撑宽（会把同一行的文字挤折行）。

**「分不清归属」几乎总是缺分隔**：

- 分组之间用 **1px 竖线**断开，不要只靠空隙（空隙会被读成"同一组的更多选项"）。
- 每个维度给一个 **11px 的组标签**，放在选项左边。
- **不同控件类型用不同形态**：单选一组 → 无边框文字按钮 + 下划线；多选/需打开面板 → 带 1px 边框的下拉按钮。**不要为了"统一"把两种交互做成同一个样子**，那才是真正的不可读。

**侧栏导航**：整行热区 34px + 16px 图标 + 悬停底色 + 选中底色/竖条。纯文字链接在 2026 年读起来"不是一个可点区域"。

### 13.10 减少动效（prefers-reduced-motion）

**不是"全部关掉"。** 全局 `*{animation:none!important}` 会破坏 `transitionend` 监听、让界面瞬移失位。

- **要去掉**：大位移、缩放、3D 旋转、视差、滚动劫持、级差级联、自动循环（跑马灯/呼吸光）、横向滑动的进度线。
- **要保留**：透明度/颜色渐变（150–200ms）、焦点环、非前庭刺激形式的进度指示、按下反馈。
- 用 `matchMedia('(prefers-reduced-motion: reduce)')` 控制 JS 动效，并监听 `change`（用户会不刷新就改系统设置）。

## 十四、弧度与表面（curvature）

### 14.1 半径是一条阶梯，不是一个值

**成熟产品的真实取值**（可查证的）：

| 系统 | 阶梯 |
|---|---|
| GitHub Primer | 3 / 6 / 12 / full |
| Notion（实测） | 4 / 6 / 10 / 12（内部 token 还有 3/8/16） |
| Radix Themes | 3 / 4 / 6 / 8 / 12 / 16 |
| Vercel | 6 / 12 / 16 / full |
| Material 3 | 0 / 4 / 8 / 12 / 16 / 20 / 28 / 32 / 48 / full |
| Linear（公开 CSS） | 4 / 6 / 8 / 12 / 16 / 24 / 32 |

**本项目采用 5 档**：`0 / 2 / 4 / 6 / full`

| 元素 | 半径 | 理由 |
|---|---|---|
| 列表行、表格、通栏面 | **0** | 密集数据界面里 12px+ 圆角会和密度打架；Notion 的行高亮是全宽行内嵌一个 6px 块，不是圆角行 |
| 列表缩略图（40–56px） | **2** | 2px 读作"印上去的图版"，4px 开始读作"App 卡片" |
| 详情页大封面（≥96px） | **4** | 2px 在大图上不足 1%，视觉上消失 |
| 按钮 / 输入框 / 搜索框（32–40px 高） | **4** | ≈ 1/8 高度。GitHub/Notion/Vercel 在同高度用 6，4 是"可辩护区间"的下界 |
| 徽标 / 标签（18–22px 高） | **2** | 印刷感的下限 |
| 浮层 / 菜单 / toast | **6** | 4px 会读成"带阴影的输入框"，不是一个独立层 |
| 浮层内的菜单项 | **2** | 6 − 4（内距）= 2 |
| 进度轨道（2–4px 高） | **2** | 实际等于胶囊 |
| 星形 / 图标 | **0（字形）** | 星是矢量字形，不是面；`border-radius` 对它无效。要打磨的是圆角连接与光学居中 |
| 状态点 / 头像 | **full** | 只给身份与状态，**永远不给封面** |

### 14.2 嵌套圆角：`max(0, 外半径 − 边框 − 内距)`

```css
border-radius: max(0px, calc(var(--r-outer) - var(--border-w) - var(--pad)));
```
- **内距 ≥ 外半径时，内层必须是 0。** 4px 外半径 + 8px 内距 → 内层 0。所以 4px 的按钮里不可能放圆角图标块。
- 只有两个圆角**相距 8–12px 以内**时才需要这套算法；间隔超过 ~24px，两个角各自独立取值。
- **内外半径相同**会产生"掐进去"的角（侧边缝宽、角上缝窄）。

### 14.3 边界与阴影：三种配方，不要混用

| 用途 | 配方 | 为什么 |
|---|---|---|
| 分隔线 | `border-top: 1px solid rgba(0,0,0,.10)` | 分隔是布局，不是高度；用阴影会糊、会暗示浮起 |
| 封面描边 | `outline: 1px solid rgba(0,0,0,.10); outline-offset:-1px` | outline 不吃布局、随圆角走、内缩后不会画到图外。**不要用带色调的 border** —— 有色描边会吸周围的色，像图像边缘脏了 |
| 按钮描边 | `box-shadow: inset 0 0 0 1px rgba(0,0,0,.14)` | Primer 的做法，避免边框改变盒模型 |
| 输入框描边 | 真 `border: 1px solid` | 表单控件在高对比度/强制色模式下必须靠真边框存活 |
| 浮层 | `box-shadow: 0 0 0 1px rgba(0,0,0,.08), 0 1px 1px rgba(0,0,0,.02), 0 4px 8px -4px rgba(0,0,0,.04), 0 16px 24px -8px rgba(0,0,0,.06)` | 第一层是"当边框用的阴影"，不吃半径；后三层是深度。浮层用外阴影，**绝不用内阴影**（内阴影读作凹槽/倒角） |

**发丝线用 1px CSS 像素**，不要全局 0.5px。在 2x/3x 屏上 1 CSS px = 2–3 设备像素，才是正确粗细；全局 0.5px 在 1x 或 1.25/1.5 缩放下会消失。

### 14.4 六条硬规则

1. **胶囊只留给一个语义**（状态点/头像）。按钮、搜索框、标签全是胶囊 = 最强的模板味。
2. **半径在所有状态下恒定**：默认 / 悬停 / 焦点 / 按下 / 禁用。焦点环跟随同一个形状。
3. **永远不要对非正方形用 `border-radius:50%`** —— 会拉成椭圆。要胶囊就写 9999px。
4. **不要给 2–6px 的 UI 用 squircle / corner smoothing** —— 不可见，且 `corner-shape` 尚未 Baseline。连续曲率只用于 ≥96px 的封面或 App 图标。
5. **深色主题不换半径**，换的是边缘与高度：描边 alpha 上调（白 .12 起）、阴影减弱、靠"更亮的表面"表达层级。直接把浅色值反相会得到看不见的边框和脏阴影。
6. **0px 全场 + 1.5px 黑描边 + 硬阴影 = 新粗野主义开发者工具**，不是纸。2–4px 的微圆角才是"纸"。

### 14.5 半径与表面的失败模式

1. 按钮 + 搜索框 + 标签全是胶囊
2. 密集表格上用 12–16px 圆角
3. 一个半径走天下，或随手取 3/5/7/9
4. 父子同半径、小间距（掐角）
5. 内半径大于外半径（凸起）
6. 0px 到底 + 1.5px 黑边 + 硬阴影
7. 同一个边缘上同时有 border + 1px ring + drop shadow（三重边）
8. 平板白卡上放大软阴影（2019 年 Bootstrap 味）
9. 胶囊里再套胶囊
10. 用被裁切的 box-shadow 做焦点环（高对比度模式下直接消失）
11. 深色主题沿用浅色的描边 alpha
12. 给 2–6px 的 UI 做连续曲率

## 十五、交互的 14 条失败模式

1. 悬停动作"看不见但可聚焦"（`opacity:0` 没有 `:focus-within`）
2. 悬停揭示导致行内重排（用宽度/`display` 切换而不是叠层交叉淡入）
3. 级差失调（12ms 不可感知 / 40ms×20 行 = 卡住）
4. 给焦点环加动画
5. 退出比进入慢
6. 菊花或骨架屏闪一下就没（<300ms 就出现的指示器）
7. 骨架屏与最终几何不一致（64px 骨架 → 88px 行，CLS）
8. 两栏滚动没预留 gutter、滚动链穿透到整页
9. 滚动劫持 / 给阅读栏加视差
10. 减少动效做成"全关"，界面开始瞬移
11. 撤销提示条在聚焦时自动消失，或 3 秒就没了
12. 乐观更新没有回滚、没有防过期响应
13. `transition: all` 与动画 `box-shadow`
14. **把悬停、焦点、选中合并成同一种"稍微深一点的底"** —— 键盘用户不知道自己在哪，鼠标用户不知道哪个是打开的。必须三条通道：底色（悬停）/ 朱红环（焦点）/ 墨黑竖条（当前）

## 十六、工作方式（不变）

1. 先读本文件，再读项目内的产品文档与既有规范
2. 出《设计简报》→ 2–3 个真正不同的方向 → 选定后出完整 token 规范
3. **规范必须带具体数字**（px / hex / 比例），能被直接翻译成 CSS 变量
4. 交付时同时给出「代价」：这个方向放弃了什么（密度 / 性能 / 代码复杂度）
5. 走查实现时，用本文件第八节的 12 条当检查表
